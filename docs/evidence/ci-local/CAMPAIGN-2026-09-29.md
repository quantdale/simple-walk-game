## New gate: `scripts/verify-ci-steps.sh` (committed, mode 100755)

* Parses `.github/workflows/ci.yml` mechanically (no hardcoded step list) and
  executes every `run:` body under the GitHub Linux default shell
  (`bash --noprofile --norc -eo pipefail`) in repository checkout order.
* `continue-on-error: true` is honored as WARN, never as failure.
* `uses:` steps are reported `SKIP (hosted …; asserted locally: …)` against
  explicit local facts (`git worktree at <sha>`, `dotnet 9.0.300`).
* Exports `GITHUB_REPOSITORY=quantdale/simple-walk-game` and a CI-style
  `RUNNER_TEMP` so the identity guard and the exactly-once/long-horizon steps
  run under realistic conditions.
* Exit codes: `0` = all reproduced steps green; `1` = a step failed;
  `2` = extraction broken.
* **Hollow-pass protection** (see “Miss recorded”): extracted run/uses step
  counts must equal the `run:`/`uses:` occurrences declared in `ci.yml`, and an
  empty extracted body fails loudly instead of passing.

## Miss recorded (repo culture: write down your own bugs)

The first two full-run attempts **falsely reported 12/14 ok**: the step
extractor expected `run:`/`uses:` at 6-space indentation while `ci.yml` uses
8-space keys with 10-space block bodies, so every body extracted empty and
every “empty script” exited 0. Symptoms: wall time inconsistent with the
claimed work. Fixed parser (8/10-space rules, blank-line handling) **and** the
two-layer hollow-pass guard above, added specifically so this failure mode can
never masquerade as success again. No decision taken during the hollow window
rested on its output — the standalone gate results above were produced by
direct script executions. A related documentation miss surfaced in the same
campaign: an early draft of this file quoted paraphrased summary numbers from
memory that the raw logs did not contain; every figure above was re-verified
character-by-character against `artifacts/ev-c4/*.log` and `dotnet test` output
before committing.

## Limits (honest scope)

* This is a Windows/Git-Bash reproduction of the Linux step *bodies*; the
  hosted Linux environment itself remains unverified until the billing block is
  lifted. A future hosted green run should be diffed against this package.
* The “publish apphost executable exists” check relies on MSYS `-x`
  resolution of `WalkGame.exe`; on Linux CI the ELF apphost is checked.
  Semantics verified equivalent by inspection, not by execution.
* WSL `bash` lacks interop on this host (`/init: No such file or directory`),
  and WSL paths additionally carry a heavy 9P I/O penalty under the pacing
  workload, so all evidence here uses Git-Bash/MSYS.
* Unity/device gates unaffected by this campaign (D-035 remains open).
