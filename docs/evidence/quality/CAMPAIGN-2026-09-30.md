Note on lines 2, 5, 6: the sibling assertion
`Assert.Equal(0, state.ProcessedRecords.Count)` was **deliberately left unchanged**.
`ProcessedRecordLedgerState` exposes a `Count` but is not `IEnumerable`, so it is not a
collection for the analyzer's purposes and the rule does not fire there. Rewriting it to
`Assert.Empty` would not compile.

Each fix is strictly *stronger*: `Assert.Empty`/`Assert.Single` assert element identity
and emptiness, not merely a count.

### 4.2 Architecture gate — the rewritten netstandard2.1 rule

The old rule grepped `<TargetFramework>netstandard2.1</TargetFramework>` out of each
csproj. Centralising settings would have removed that literal from all three files and
hollow-passed the rule on every layer. The rule now reads the effective MSBuild property.

| Fixture | Result |
|---|---|
| healthy tree | `ARCHITECTURE CHECKS: 11 passed, 0 failed`, exit 0 |
| `WalkGame.Domain.csproj` → `net9.0` | exit 1, `FAIL: WalkGame.Domain is targeting net9.0, not netstandard2.1` (11 passed, 1 failed) |
| property removed from the csproj entirely, declared `netstandard2.1` in `src/Directory.Build.props` | exit 0 (correct — that is a legitimate `netstandard2.1` layer, and the grep would have wrongly failed it) |
| same, with `src/Directory.Build.props` set to `net9.0` | exit 1, `FAIL: WalkGame.Domain is targeting net9.0, not netstandard2.1` — **the case a grep would have missed entirely** |
| restored | 11 passed, 0 failed |

The rule also fails closed: if the `dotnet` CLI is absent or the project cannot be
evaluated, it reports a FAIL saying the rule was *not checked*, rather than passing. A
self-check reads the property for `tests/WalkGame.Domain.Tests` (legitimately `net9.0`)
and reports a FAIL if the reader returns a constant or cannot evaluate.

## 6. Scope notes / things deliberately NOT done

- **No dependency was upgraded.** `System.Text.Json` stays 8.0.5, xUnit 2.9.2,
  `Microsoft.NET.Test.Sdk` 17.12.0, `xunit.runner.visualstudio` 2.8.2,
  `coverlet.collector` 6.0.2. Bumping during a pinning change would confound the result.
- **`dotnet format` was not adopted as a gate.** `TESTING_AND_RELEASE.md` §16 records that
  as a considered decision and this change does not reopen it.
- **No source reformatting.** In particular, `ci.yml` still has 11 over-length lines.
  Verified by count: 11 at `HEAD`, 11 after this change, **0 introduced** by this change.
  The `run:` bodies cannot be reflowed without changing the exact text CI executes, which
  is the drift `verify-ci-steps.sh` exists to prevent. Recorded here rather than silently
  ignored.
- **Hermetic/containerised builds remain deferred** as disproportionate for a
  single-developer-quality repository.
- **Hosted CI remains unverified** (KI-001, account billing). Nothing in this document
  should be read as a hosted-CI result.
